# `POST /v1/prices/lookup`

Identity-aware Mainnet USD pricing for Stellar assets. This endpoint is
separate from the legacy symbol-based `GET /v1/prices`, which remains
unchanged during client migration.

## Request

```json
{
  "assets": [
    { "type": "native" },
    {
      "type": "classic",
      "code": "USDC",
      "issuer": "GA5ZSEJYB37JRC5AVCIA5MOP4RHTM335X2KGX3IHOJAPP5RE34K4KZVN"
    },
    {
      "type": "contract",
      "contract_id": "CCW67TSZV3SSS2HXMBQ5JFGCKJNXKZM7UQUWUZPUTHXSTZLEO7SJMI75"
    }
  ]
}
```

- Auth: none; the existing global public/IP rate limit applies.
- Network and quote currency are fixed to Mainnet and USD.
- `assets` must contain 1–25 entries. The limit is checked before server-side
  deduplication.
- Unknown fields, kinds, invalid StrKeys, and invalid kind/field combinations
  return HTTP 400.
- Asset-code case is significant and preserved. Issuer and contract StrKeys
  are normalized to uppercase.

## Response

```json
{
  "data": {
    "native": { "price": "0.204512", "change_24h": null },
    "classic:USDC:GA5ZSEJYB37JRC5AVCIA5MOP4RHTM335X2KGX3IHOJAPP5RE34K4KZVN": {
      "price": "1.001152",
      "change_24h": null
    },
    "contract:CCW67TSZV3SSS2HXMBQ5JFGCKJNXKZM7UQUWUZPUTHXSTZLEO7SJMI75": {
      "price": "1.001152",
      "change_24h": null
    }
  },
  "currency": "usd"
}
```

Response keys are generated by the server:

- `native`
- `classic:<case-sensitive-code>:<issuer>`
- `contract:<contract-id>`

Valid identities that are unsupported or currently unavailable are present
with a `null` value. Clients must not interpret `null` as a zero price.
`change_24h` is explicitly `null`; the StellarExpert operation used here does
not provide a trusted 24-hour change.

Contract identities are priceable only when StellarExpert metadata names
native XLM or an underlying classic asset and the SDK-derived Mainnet Stellar Asset Contract
address exactly matches the requested contract. Ordinary Wasm/SEP-41 contracts
therefore return `null`. There is no symbol or CoinGecko fallback on this path.

For valid requests, lookup returns HTTP 200 even when some or all entries are
unavailable. Valid prices and existing cache hits survive failures for other
identities. Malformed or duplicate provider records leave the affected identity
null and are not negatively cached. Confirmed omissions and unsupported contracts
may be cached for 60 seconds, as may successful prices. Malformed envelopes,
provider errors, and oversized responses do not establish definitive absence.

Cache reads and the single batched write each use a 200 ms timeout, with bounded
socket I/O as well. A failed read disables cache writes for that request; cache
failure does not change a successful provider lookup into an HTTP error.

The Swagger 2 schemas use `x-nullable` for nullable price-map values and
`change_24h`. Clients whose generators ignore this extension must still model
the response as a map of price objects **or null**.
